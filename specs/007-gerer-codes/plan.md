# 007 — Gérer ses codes depuis son téléphone : plan

**Statut** : Validé

## 1. Résumé

On construit les deux écrans où l'on se sert de son code : la page `/reservation`, ouverte depuis l'accueil par « Retrouver ma réservation », et la page du lien de gestion, `/trajets/<id>/gestion`. Une fois les six tâches terminées, le supporter retrouve son billet avec son code, voit s'il est actif ou annulé, l'annule et l'envoie sur WhatsApp ; le conducteur ouvre son lien de gestion, y reconnaît son trajet, puis l'annule en saisissant son code de gestion. Côté API, on ajoute une seule lecture, celle d'un trajet par son identifiant, qui ne montre que ce que la liste des départs montre déjà et dit si le trajet est annulé ; les routes de consultation et d'annulation de TR3 existent déjà et ne changent pas. Les tâches vont de l'API vers les écrans : la lecture du trajet et son pendant dans la fausse API, la page du supporter, l'annulation de sa réservation, l'envoi du billet sur WhatsApp, la page du conducteur, puis les refus en français. Retrouver un code perdu, modifier une réservation ou un trajet et prévenir les passagers restent hors périmètre.

Les mots de la spec et leur nom dans le code :

| ---------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------- |

| « Retrouver ma réservation » | lien de `hero.tsx` vers `/reservation`                | L'accès visible sur l'accueil vers la page où le supporter saisit son code.                       |

## 4. Erreurs

Aucun code d'erreur n'est créé. La lecture d'un trajet réutilise `TRIP_NOT_FOUND`, et les écrans affichent en français les refus que l'API renvoie déjà.

| Code AppError             | Catégorie  | HTTP | Quand                                                                                                                                        | Scénario |
| ------------------------- | ---------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `TRIP_NOT_FOUND`          | NOT_FOUND  | 404  | Le lien de gestion ne désigne aucun trajet, à l'ouverture ou à l'annulation : « Ce trajet est introuvable. Vérifiez votre lien de gestion. » | AS7      |
| `BOOKING_NOT_FOUND`       | NOT_FOUND  | 404  | Aucune réservation n'a ce code : « Aucune réservation ne correspond à ce code. Vérifiez-le. »                                                | AS7      |
| `MANAGEMENT_CODE_INVALID` | FORBIDDEN  | 403  | Le code saisi n'est pas celui du trajet : « Ce code de gestion n'est pas le bon. »                                                           | AS7      |
| `VALIDATION_FAILED`       | VALIDATION | 400  | Le code envoyé est vide ou trop long : « Saisissez votre code. »                                                                             | AS7      |

Tout autre refus (panne, réseau) affiche « Une erreur est survenue, réessayez », comme le retient la spec. Un lien de gestion dont l'identifiant est mal formé reçoit 400 `VALIDATION_FAILED` à la lecture : la page affiche alors le message du trajet introuvable, puisqu'aucun code n'a encore été saisi.
